# wu2007

An ordered-statistics decoder for the (174,91) LDPC code shared by FT8 and FT4,
using the main search and preprocessing methods described by Wu and Hadjicostis
(2007). A codeword contains 77 payload bits, 14 CRC bits and 83 parity bits.

Use `wu2007::Decoder` to decode `&[f32; 174]` in natural codeword order.
Inputs must be finite. See the [crate-level LLR convention](../src/lib.rs).

```rust
use ft8_ldpc::wu2007::{Config, Decoder, Status};

let llr = [4.0_f32; 174];
let mut decoder = Decoder::new(Config::default()).expect("valid configuration");
let result = decoder.decode(&llr);

assert_eq!(result.status, Status::Success);
assert!(result.crc_valid);
assert_eq!(result.payload, [0; 2]);
```

Reuse the decoder for subsequent codewords. With candidate collection disabled,
decoding allocates no heap memory after construction.

Configuration uses public fields, `Default`, and `validate()`. Construction
validates the cascade size before the combined search and preprocessing order.
Both errors have typed `ConfigError` variants. Prefix lengths are clamped to the
available redundancy, and options for disabled preprocessing stages are ignored.

Run the commands below from the repository root.

## What it decodes

- Main search orders 0 to 6 (with first preprocessing on, 0 to 5), first
  preprocessing at order w + 1, and optional second preprocessing at order
  w + 2 (`enable_second_preprocessing`, `second_preprocessing_prefix_len`;
  w from 0 to 4).
- Cascade settings 0 to 14, one-word and two-word parity-prefix
  paths, candidate lists, CRC-valid candidate preference, and any candidate cap
  (`Decoder` accepts a cap of 0 and returns the empty result).
- Basis reduction uses the unblocked kernel, with reliability-descending
  redundancy order by default.

`selection_policy` controls which searched candidate wins:

- `SelectionPolicy::BestCrcValid` (the default) prefers the lowest-distance
  CRC-valid candidate, falling back to the lowest-distance candidate if none
  passes CRC.
- `SelectionPolicy::MinMetricThenCrc` chooses the lowest-distance candidate
  first, then checks its CRC.

Both policies keep the first searched candidate at an exactly tied distance,
using a strict `<` comparison. Selection is independent of acceptance:
`require_crc = false` relaxes success and the baseline zero-hard-error early
stop without changing the winner. A CRC-invalid minimum gives `NoValidCrc`
when CRC is required, or `Success` otherwise; a cap-limited search still gives
`CandidateCapHit` with its selected candidate, under either policy.

`DecodeResult` includes the selected codeword and messages as packed `u64`
arrays, with bit zero in the least significant position. `llr_distance` is the
sum of input LLR magnitudes at positions where the candidate differs from the
hard decision. An empty result has infinite distance and zero message words.
`Diagnostics` and collected `Candidate` records preserve the search counts and
candidate order.

## Correctness

```sh
cargo test --workspace
```

Seeded tests encode random payloads and check that decoding recovers the
codeword, including cases with hard-decision errors that require the main
search or second preprocessing. Tests also cover allocation-free decoding
with candidate collection disabled, configuration validation, CRC selection,
candidate caps, CRC and encoding vectors, and kernel comparisons against
reference implementations with fresh and reused decoders.

The CRC and encoder vectors are in
[`tests/fixtures/known-answer/`](../../../tests/fixtures/known-answer/).
Test builds use the optimized profile configured in the root manifest.

## Algorithm reference

Yingquan Wu and Christoforos N. Hadjicostis, "Soft-Decision Decoding of Linear
Block Codes Using Preprocessing and Diversification," IEEE Transactions on
Information Theory, vol. 53, no. 1, January 2007,
[doi:10.1109/TIT.2006.887478](https://doi.org/10.1109/TIT.2006.887478).
